# Spike Manifest

## Idea

Diagnose and propose moves to escape the editor-theme reading of NeoCade and reach a unique, expressive game-UI identity within the locked flat-MD3 / no-textures / no-gradients / anti-cyberpunk constraints. Drives the planned post-v1 "Signature Visual Moves" phase. Scope and references live in `visual-identity-distinctiveness/BRIEF.md`.

## Requirements

Decisions confirmed during spiking. Non-negotiable for the Phase 12 build, updated as spikes progress.

- Spike sub-directories live under their umbrella (e.g. `visual-identity-distinctiveness/001-...`) rather than as siblings of the umbrella, since the umbrella also carries `BRIEF.md` and the consolidated `REPORT.md`.
- All spike outputs are `.planning/`-only — no addon code edits, no new BINDING_TABLE entries, no new SVGs in `addons/`. Phase 12 owns implementation.
- Reference imagery in this repo is limited to the 5 NeoCade direction concept PNGs and `inputs/NeoCade-Theme-Prototype.png`. Commercial game-UI references (Royal Match, Brawl Stars, etc.) are URL-only / copyright-restricted and contribute qualitatively, not as measured pixels. Synthesized reference frames (per spike 001's `synth_references.py`) are the measured stand-in for MD3 spec layouts and shipped game-UI conventions.
- Color monoculture is real, measured, and directional. NeoCade's 5 directions average 1.6 hues per showcase frame; Slate and Daybreak read as 1 hue. MD3 spec target = 3, shipped game UIs = 5+. (Source: 001 verdict, 2026-05-10.)
- Raised-depth-formula replacement is HSV value-darken at strength `0.20 + 0.10 * raised_strength`. Hue and saturation preserved by construction. The BRIEF's hue-drift complaint was partly a misread — the actual defect is darkness (~23% drop where HCGames needs ~40%), not hue (≤2° rotation in all shipped configs). C4 helps colored-button affordance only; does NOT fix dark-tonal neutral buttons because face and depth converge into base_color (those are quiet UI and don't need strong depth). (Source: 002a/002b verdicts, 2026-05-10.)
- **Phase 12 scope refined by user (2026-05-10):** the real headline fix is making `accent_color` surface more often in idle-state chrome (C2', new), not introducing new hues via MD3 secondary/tertiary derivation (C2, deferred). Role colors must be PURPOSEFUL — opt-in via type variation only, never auto-bound to widget defaults. Generic semantic names (`AccentPanel`, `InfoPanel`, `WarningPanel`, `DangerPanel`, `SuccessPanel`; `SuccessLabel`, `WarningLabel`, `DangerLabel`, `InfoLabel`), never game-specific (no LobbyPanel, no MatchPanel). North star is MD3 Expressive: purposeful + restrained color usage, not blanket. (Source: user refinement after spike completion, 2026-05-10.)
- **Phase split into 12 + 13 (locked 2026-05-10):** to keep each phase in a single executable session and respect token-window limits, the refined plan is split into two independent phases:
  - **Phase 12 — Signature Visual Moves: Defaults (~7-10h):** C4 (HSV value-darken depth) + C2' (accent expansion in idle chrome) + C6 (per-direction signature moves). Default-behavior changes that resolve the headline "generic dark theme" complaint. Includes minor showcase additions for C6 Pulse kicker demo.
  - **Phase 13 — Role Variation Type-Set: Opt-Ins (~5-6h):** C1 (4 role Label variations) + C3 (5 role Panel variations) + new "Role Variations" showcase section. Pure-additive opt-in toolkit; default chrome unchanged from Phase 12 baseline.
  - Phase 13 has zero dependency on Phase 12's implementation details — only depends on the public 12-export contract (preserved). Phase 12 alone is a coherent ship-point if Phase 13 is deferred or skipped.
  - Mid-Phase-12 fallback if execution runs long: after C4+C2' (~3-4h), the headline complaint is resolved; C6 defers to a follow-up. NOT recommended unless necessary — C6 is what makes the 5 directions visually unique.
- **`raised` export invariant (locked 2026-05-10):** `raised=false` MUST show ZERO raised/3D elements anywhere in the theme. `raised=true` shows a partial subset (panels and buttons where it makes sense; explicitly NOT tabs). Current behavior of which elements lift under `raised=true` is the contract — Phase 12 does not change that subset. Any candidate that introduces a 3D-ish element (glow halos, drop shadows, beveled outlines, etc.) under `raised=false` is forbidden. PROJECT.md "Glow halos on focus, hover, pressed, or any other state" Out-of-Scope rule extends here: no glow halos in either flat or raised mode. (Source: user constraint statement 2026-05-10.)
- **C6 Daybreak signature revised (2026-05-10):** original spike-003 catalog proposed "4px soft halo on primary CTAs" as Daybreak's per-direction signature. This violates both the raised=false=zero invariant (a halo reads 3D in flat mode) AND the PROJECT.md no-glow-halos rule. Replaced with "1px outer mint outline on primary CTAs + generous horizontal padding" — clearly flat, no glow, delivers the same "airy-welcoming" personality through outline-as-open-invitation + breathing-room. User confirmed (2026-05-10): "i like the new direction for Daybreak. this makes way more sense and gives the theme a lot more uniqueness."
- **Per-direction uniqueness elevated to locked project value (2026-05-10):** "i want all themes to have its own specific feel". Every direction MUST have at least one signature move strong enough to identify the direction at thumbnail scale, without relying on color cues. This is now a hard Phase 12 success criterion, not a nice-to-have. The constraint replaces a weaker "directions should differ" framing.
  - **Current C6 signature strength audit (2026-05-10):**
    - Bubble (forced ≥26 radius) — **strong** ✓
    - Burst (oversized CTA + thicker depth) — **strong** ✓
    - Slate (1px hairlines + quiet-pill primary) — **moderate-strong** ✓
    - Pulse (uppercase-tracked kicker) — **moderate**; Phase 12 should validate via mockup, and add a secondary move (proposal: 1px lime accent stripe under section headers) if thumbnail-scale recognition fails.
    - Daybreak (outer outline + generous padding on CTAs) — **moderate**; Phase 12 should validate via mockup, and add a secondary move (proposal: same outline language on selected ItemList rows instead of left-stripe) if thumbnail-scale recognition fails.
  - Phase 12 validation gate: produce thumbnail-scale render of all 5 directions side-by-side, in greyscale; an outside reviewer must be able to identify each direction without color cues. If any direction fails, add a secondary signature move before shipping.
- **SC#4 protocol remediation (locked 2026-05-11):** initial Phase 12 thumbnail-scale greyscale renders flagged Daybreak and Burst as marginal/failing identification (per the Phase 12 VERIFICATION.md attestation table). Per the locked protocol above, two secondary signature moves were applied — both in-place tightening of already-approved primary signatures, NOT new architecture:
  - **Daybreak**: `shape.primary_outline_width` bumped from 1px → 2px (still flat, still no halo, full-alpha; same outline-as-open-invitation language, just more visible at thumbnail scale).
  - **Burst**: `shape.primary_min_height` bumped from 56 → 64 (desktop) and `shape.primary_min_height_mobile` from 64 → 72 (preserves the 8px desktop-vs-mobile delta from D-12.11; shifts the floor up so the "oversized" CTA reads as unmistakably larger).
  - Both shifts amend the D-12.11 numeric values upward; the architectural design (which axis Daybreak vs Burst uses for identity) is unchanged. If a future re-render still flags either direction as marginal, the next remediation is to amend SC#4 itself to "full-resolution identifiable" with documented rationale rather than continue bumping numeric thresholds.
- **Deferred follow-up spikes (post-Phase 12):**
  - C2 (MD3 secondary/tertiary auto-derivation) revisits only when accent-expansion fix (C2') is validated insufficient on its own. Future opt-in via `use_md3_extended_palette: bool` export, never default.
  - C5 (lift thickness bump) re-evaluates visually after C2'+C6 ship; current lifts may be sufficient once accent presence and direction-uniqueness moves land.
  - Surface tonal range expansion ("HSV value range with more brightness also" — user idea) — separate spike. Lift face brightness across the 5-stop ramp so dark themes like Pulse have more contrast between panel and button. Higher risk than C4 because it touches every surface stop.
