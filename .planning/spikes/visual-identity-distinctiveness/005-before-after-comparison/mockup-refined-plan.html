OPT-IN ONLY

Role variations (C1 + C3)

applied via theme_type_variation — never bound to widget defaults
These are not part of the baseline chrome. Consumers apply them deliberately when a Label or Panel semantically represents success / warning / danger / info / accent state. The showcase scene will include a "Role Variations" demo section so consumers see they exist. They do NOT auto-tint any existing widget.

C1: Label variations

✓ SuccessLabel — Quest complete!
⚠ WarningLabel — Low inventory.
✕ DangerLabel — Connection lost.
ℹ InfoLabel — New patch available.
my_label.theme_type_variation = "SuccessLabel"

C3: Panel variations

AccentPanel — generic accent-tinted container
InfoPanel — informational state container
WarningPanel — non-blocking warning
DangerPanel — blocking error or destructive action
SuccessPanel — confirmation state
Purposeful use only. A normal Panel stays neutral. A Panel only becomes role-tinted when the consumer explicitly tags it with the corresponding type variation. Same model for Labels. Zero baseline chrome changes from C1 and C3 — they only become visible when consumed.

Honest disclaimers

  • HTML mockup, not Godot rendering. CSS does what Theme/StyleBox can do, but exact pixel rendering will differ slightly when implemented in Godot. The mockup is for spirit/direction approval, not pixel-perfect preview.
  • Game-shaped layout used here is illustrative. The actual NeoCade showcase/showcase.tscn is tool-shaped (control gallery). Phase 12 will add a "Game UI Demo" section to the showcase to render these layouts in real Godot, then capture-script will produce after-shots that go into comparison.html.
  • Layout is approximate. Real implementation will respect existing showcase scaffolding; this mockup just demonstrates which chrome slots gain accent under C2' and which signatures define each direction under C6.
  • Same color palette per direction — zero new hues. Every color shown is either the direction's existing base_color, accent_color, panel tone, or the same-hue darker depth via HSV value-darken (C4). No MD3 secondary/tertiary derivation here (that's deferred C2). Role colors only appear in opt-in variation demos (bottom section).
