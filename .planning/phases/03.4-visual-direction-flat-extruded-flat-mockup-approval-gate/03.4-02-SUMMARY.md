## What changed from the first execution

The first execution rendered 15 PNGs in which every direction looked like the same template with only color tokens swapped — the user's word: "every theme looks like the same, only with a color difference." On audit, the artboard CSS hard-coded `--radius: 12px` for all five directions and provided no per-direction shape-language hooks.

This re-execution:

1. Removed the hard-coded shape token from `src/neocade-mockups.css` and refactored the `.nc-artboard` rule to read every shape-language value from per-direction CSS variables (`--radius-base`, `--radius-button`, `--radius-tab`, `--radius-mark`, `--button-pad-h`, `--density-padding`, `--focus-thickness`, `--raised-primary-offset`, etc.).
2. Mirrored the `data/directions.json` `shape_language` blocks into the JS renderer's `NEOCADE_DIRECTIONS[*].shape` so the file:// runtime has all values without needing fetch.
3. Added structural variant attributes per direction: `data-tab-shape`, `data-mark-shape`, `data-primary-strategy`, `data-ghost-strategy`, `data-focus-style`, `data-kicker-style`, `data-lift-tabs`, `data-lift-rows`, `data-lift-secondary`. The CSS routes each variant through these attributes (e.g., `[data-mark-shape="square-cabinet-bezel"] .nc-art-mark` for Pulse vs `[data-mark-shape="circle-or-squircle"] .nc-art-mark` for Bubble).
4. Switched the raised-mode hard offset from `::before` + `z-index: -1` (which painted on top of the button background — buggy) to the classic `box-shadow: 0 var(--raised-X-offset) 0 0 var(--offset)` hard-offset pattern. This is the standard flat-3D Game UI technique.
5. Replaced the bundled-Codex-runtime Playwright dependency with locally-installed `playwright-core` driving system Microsoft Edge — no browser download, deterministic on the user's box, isolated under a local-only `.gitignore`.
