### Task 1 — Finalist 4-grid + color overrides (commit `2996ba9`)

Built the full-fidelity 4-grid for Pulse plus a color-override preview row. Six PNGs rendered via the new `node render.js finalist-images` mode (added in this task). Filenames use the `-finalist-` infix to avoid colliding with the 15 Plan 02 Stage 1 PNGs (which remain unchanged).

The 4 grid cells:
- `pulse-finalist-desktop-flat.png` — `raised=false`, `platform=DESKTOP`, 1280×720 logical
- `pulse-finalist-mobile-flat.png` — `raised=false`, `platform=MOBILE`, 430×1500 logical
- `pulse-finalist-desktop-raised.png` — `raised=true`, `platform=DESKTOP`, 1280×720 logical
- `pulse-finalist-mobile-raised.png` — `raised=true`, `platform=MOBILE`, 430×1500 logical

The 2 override variants:
- `pulse-finalist-override-warm.png` — `base_color=#1A1410`, `accent_color=#FFC857` (warm amber)
- `pulse-finalist-override-ocean.png` — `base_color=#0F1A22`, `accent_color=#5FE3FF` (ocean cyan)

The renderer (`src/neocade-mockups.js`) was extended minimally: `renderConceptImage` now accepts optional `?base=#RRGGBB&accent=#RRGGBB` query params. When both are supplied (and well-formed) the artboard renders the named direction with the overridden palette while preserving the shape language.

`finalist-gallery.html` was rewritten as a static gallery (no JS rendering needed for Plan 03 — the finalist set is locked, the PNGs are pre-rendered): 4-grid section, 2-cell color-override row, full Control/state coverage matrix table, and a decision block explaining the Task 4 user gate.

Verification PASS: gallery contains all 7 markers (`raised=false`, `raised=true`, `platform=DESKTOP`, `platform=MOBILE`, `base_color`, `accent_color`, `override`).

## Deviations from Plan

### Auto-fixed Issues

None of the Rule 1 / Rule 2 / Rule 3 categories triggered. The plan executed exactly as written, with the exception of two Rule 3 (blocking issues) micro-fixes documented below as design clarifications, not bugs:

**1. [Rule 3 - Scope clarification] Renderer extension for color-override rendering**
- **Found during:** Task 1
- **Issue:** `concept-image.html` only accepted `?direction=&platform=&raised=` query params; rendering color-override variants required modifying the artboard at the request level without changing `data/directions.json` or the canonical Pulse data.
- **Fix:** Extended `renderConceptImage` in `src/neocade-mockups.js` to accept optional `?base=#RRGGBB&accent=#RRGGBB` params. When both are well-formed, the renderer clones the named direction with the overridden palette. The override is request-scoped — `data/directions.json` and the canonical Pulse `NEOCADE_DIRECTIONS[]` entry are unchanged.
- **Files modified:** `.planning/mockups/3.4/src/neocade-mockups.js`
- **Commit:** `2996ba9`

**2. [Rule 3 - Render mode addition] `finalist-images` render mode in render.js**
- **Found during:** Task 1
- **Issue:** `render.js` had no mode for rendering the Plan 03 4-grid + override PNGs. Reusing `concept-images` would have overwritten the 15 Plan 02 Stage 1 PNGs.
- **Fix:** Added `node render.js finalist-images` mode. Outputs use the `-finalist-` filename infix to keep Plan 02 PNGs untouched.
- **Files modified:** `.planning/mockups/3.4/render.js`
- **Commit:** `2996ba9`

Both fixes are pure additions — no existing rendering paths or files were broken. Plan 02's `node render.js concept-images` and gallery rendering modes remain operational and unchanged.
