    Create or update `.planning/DESIGN_TOKENS.md` using the required sections from `<interfaces>`.

    The document must be implementation-ready for Phase 4. It must include:
    - approved final theme list
    - recommended starter direction and its default direction-resource values
    - per-direction data-resource recipes for all approved themes
    - class names and `.tres` filename stems
    - default `base_color` and `accent_color`
    - radii, outline, spacing, typography, state-layer, and surface-ramp formulas or recipe values
    - flat variation rules

    - anti-texture and anti-cyberpunk rules

    - explicit no-subclass production contract

    Per architecture simplification 2026-05-06e (see `03.4-CORRECTIVE-ADDENDUM.md` D-31), document that:

    - `NeoCadeTheme` is a **single concrete class** at `addons/neocade_theme/neocade_theme.gd` (`@tool class_name NeoCadeTheme extends Theme`). NOT abstract. Users can instantiate directly to author custom themes.
    - The class has **9 `@export` properties total** (finalized 2026-05-06f). Core (4): `base_color`, `accent_color`, `raised`, `platform`. Shape (5, under `@export_group("Shape")`): `corner_radius`, `spacing`, `raised_strength`, `focus_thickness`, `outline_width`. The `@export` set is intentionally minimal — limited to values that should be consistent across the entire theme. Per-direction unique mood lives in Theme Editor entry overrides per `.tres`, NOT in a long list of exports.
    - Dark/light handling is luminance-derived: `var is_light: bool = base_color.get_luminance() >= 0.5` is computed in `_regenerate_theme()` (dark default; `is_light` flags deviation); all conditional formulas branch on `is_light` (godot-minimal-theme line-56 pattern with renamed/inverted variable). No separate `light_mode` toggle in v1.
    - Convention: any future paired x/y `@export` values use `Vector2i`.
    - Each approved direction is purely **data**: a `.tres` file `[gd_resource type="NeoCadeTheme" format=3]` at `addons/neocade_theme/{name}_neocade_theme.tres` with its specific `@export` values saved. **No per-direction `.gd` files.**
    - The flat addon layout: **1 `.gd` + N `.tres`** all at the addon root `addons/neocade_theme/`. **No `_dev/` subfolder, no `themes/` subfolder, no root `neocade_theme.tres` file.** (`fonts/` and `icons/` subfolders are preserved for asset organization.) For the v1 approved set of 5 directions: 1 `.gd` + 5 `.tres` files at the addon root.
    - The Phase 3.4 approval-gate user pick designates the **recommended starter direction**. The recommended starter has no separate file; it is simply the direction that is preloaded as the default theme in the showcase scene (`showcase/showcase.tscn`) and named in the addon README's "try this first" suggestion.
    - Consumer pattern: `preload("res://addons/neocade_theme/{name}_neocade_theme.tres")` — always pick a direction by name. Custom theme: instantiate `NeoCadeTheme.new()` and set `@export` values, or save your own `.tres` of type `NeoCadeTheme`.
    - Phase 4 must delete the existing empty-Theme scaffold at `addons/neocade_theme/neocade_theme.tres` since no root `.tres` ships.

    Translate the Phase 3.4 mockup `.planning/mockups/3.4/data/directions.json` `shape_language` blocks (which encode each direction's commitment on the 10 shape-language axes from the spec) into concrete `@export` values per direction. Phase 4 sets these values when creating each per-direction `.tres`.
