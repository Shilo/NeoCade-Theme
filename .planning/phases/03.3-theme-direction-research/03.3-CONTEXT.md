## Implementation Decisions

### Theme Direction Derivation Strategy

- **D-01 (Names: keep, revise, or replace based on fit):** Direction names are NOT under a hard "must be new" restriction. Each candidate direction's name is chosen based on what fits best:
  - **Keep a v0 name** if the user's reactions indicate the *concept* should survive (with universal revisions applied — see D-01c). Example: if user liked Prize Pop Plaza's playful personality + raised buttons, keeping the name preserves that lineage; the *direction* gets revised but the *name* signals continuity.
  - **Revise a v0 name** if it's close but the personality has shifted enough that the name no longer fits. Example: "Cabinet Chrome" → "Cabinet Modern" if the chrome/3D framing is dropped but the LDtk-color professionalism is kept.
  - **Replace a v0 name** if research surfaces a stronger archetype not represented by v0 (e.g., a fully MD3-Expressive saturated direction with no v0 ancestor; a daylight-friendly direction not in v0 at all).
  - **Reject a v0 name entirely** if the user explicitly rejected the *concept* (Boardwalk Sunset — DROP entirely; do NOT carry the name forward).

- **D-01b (Base-direction selection deferred to Phase 3.4):** Phase 3.3 produces 5 *peer* candidate directions — none is pre-designated as the "base". At the Phase 3.4 approval gate, the user picks ONE of the approved directions to be the **`NeoCadeTheme` base** (the one whose values become the superclass defaults; consumer instantiating `NeoCadeTheme` directly gets that direction's style). The other approved directions become personality subclasses (`{Name}NeoCadeTheme extends NeoCadeTheme`). Phase 3.3 produces all 5 with **equal ambition** so the user has a meaningful choice; do NOT bias one direction as "more base-y" than another. The base pick is a TASTE decision — "which is most universal or pretty" — and that decision belongs to the user at Phase 3.4, not the planner at Phase 3.3.

- **D-01c (Universal revisions apply to ALL 5 directions, regardless of name):** Whether a direction keeps a v0 name, revises it, or is brand-new, **every** direction has the universal redirect rules applied:
  - No textures, no patterns, no embossing, no painterly/leather/wood/grunge backgrounds, no gradients on chrome (Phase 3 redirect locks)
  - Anti-cyberpunk discipline preserved (no synthwave / no neon-noir / no dystopian)
  - Flat MD3 / MD3 Expressive language is the visual idiom
  - Optional extruded-flat raised variation per Flat-3D Game UI pattern
  - Inter Variable Roman typography only (Option D)
  - Generated dynamically via `NeoCadeTheme` superclass + `@export` props (per Phase 3.2 architecture)
  This means even if "Prize Pop Plaza" the name survives into Phase 3.3, "Prize Pop Plaza" the *visual treatment* is fundamentally re-rendered through these filters — no painterly chrome, no embossed buttons; just flat solid colors + optional extruded-flat depth on raised. Same for any other surviving v0 name.
- **D-02 (Primary inputs, in priority order):**
  1. **User's new goal:** "colorful, flat and modern UI. Not outdated 3d, texture and engraving... It can still remain colorful and playful and expressive." (verbatim from 2026-05-04 redirect)
  2. **User's hard restrictions:** No textures. No patterns. No embossing. No painterly/leather/wood/grunge backgrounds. No gradients on chrome. Anti-cyberpunk (no synthwave/neon-noir/dystopian).
  3. **User's exemplar references:** [hcgamestudios flat-game-ui-for-mobile-games](https://hcgamestudios.itch.io/flat-game-ui-for-mobile-games), [fajrulaslim UI Button Flat Design](https://fajrulaslim.itch.io/ui-button-flat-design) — the user's literal "this is what I want" examples.
  4. **User's per-v0-direction reactions** (see D-04 below) — used as DNA, with names eligible to survive per D-01 fit-based selection.
  5. **Phase 3.1 findings:** MD3 + MD3 Expressive design language affordances; Flat-3D Game UI extrusion patterns.
- **D-03 (5 directions cover personality space; Direction Set = "Keep broad spread"):** The 5 directions span distinct *personality archetypes* derived from the inputs above. **Direction Set selection (user, 2026-05-06): "Keep broad spread"** — the recommended option from the Direction Set decision. The 5 directions deliberately cover variety (e.g., dark saturated arcade, modern minimal dark, playful bubbly, friendly daylight, expressive statement) rather than clustering all directions in one mood band. Each direction must:
  - Have a name chosen per D-01 (keep / revise / replace v0 names per fit; only Boardwalk Sunset is hard-rejected)
  - Be derived from the user's goals + restrictions + DNA + Phase 3.1 research findings
  - Demonstrate a distinct personality / palette / mood (so v1 ships variety, not 5 similar dark themes)
  - Have universal anti-texture / flat-MD3 revisions applied (per D-01c) — surviving v0 names get the *visual treatment* fully re-rendered, even if the *name* lineage continues
  - **Stand on its own personality** — NOT differentiate from peer directions via flat-vs-raised or desktop-vs-mobile axes (those are universal exports — see D-03b)

- **D-03b (Universal axes — NOT direction-differentiation axes):** Per Phase 3.2 architecture lock, **every** approved theme's `.tres` exposes the same `@export` axes via `NeoCadeTheme` superclass: `raised: bool` (flat ↔ extruded-flat), `platform: {DESKTOP, MOBILE, AUTO}`, `base_color: Color`, `accent_color: Color`. This means:
  - **EVERY direction must work in BOTH flat AND raised modes** — no direction can be "the raised theme" or "the flat theme"; raised is a consumer toggle that every direction's formulas must handle gracefully (e.g., the playful direction's raised mode is bouncy candy buttons; the modern minimal direction's raised mode is restrained 1px offset shapes — but BOTH directions support BOTH modes).
  - **EVERY direction must work in BOTH DESKTOP AND MOBILE sizings** — no direction can be "the mobile-only theme" or "the desktop-only theme"; sizing is a consumer toggle that every direction's constants/font-sizes must handle gracefully (mobile floors WCAG-compliant per D-19 of Phase 3.2 contract).
  - **Directions differentiate on PERSONALITY, PALETTE, MOOD, SHAPE LANGUAGE INTENT, ACCENT BEHAVIOR** — not on which export axes they support.
  - Implication for archetypes: any seed archetype name suggesting "playful raised" or "mobile-friendly bright" is reframed to remove the universal-axis qualifier — the personality is what matters; raised + mobile are givens. (See D-06 reframe below.)
- **D-03c (Execution permitted to expand research if 5 personality-distinct directions require it):** If the planner/executor finds that 5 *truly* personality-distinct directions (per D-03 + D-03b) cannot be derived from the seeded archetype space + the initial 10-15 commercial examples, **execution may expand the survey** (more commercial examples, additional MD3 Expressive showcases, additional flat-MD3 mobile games / web apps / itch.io packs / Unity Asset Store packs / Dribbble cases / hand-crafted exemplars) **without escalating** — this is a research-quality concession the user has pre-approved. Constraints stay locked: hard restrictions (D-02 #2), anti-cyberpunk + anti-texture filters (D-07), Inter-only typography (D-16), flat MD3 / extruded-flat idiom only. The deliverable is 5 *uniquely personality-distinct* directions, not 5 close variations padded out to hit a number.

## Specific Ideas

- **The user explicitly asked for a phase that researches theme directions and generates 5 new themes per their goals.** That's Phase 3.3's exact mandate.
- **Direction Set choice (user, 2026-05-06): "Keep broad spread" (Recommended).** 5 distinct personality archetypes — dark saturated arcade / modern minimal dark / playful bubbly / friendly daylight / expressive statement — NOT 5 dark variations, NOT a no-daylight cluster.
- **Universal axes ≠ direction differentiation axes (CRITICAL).** Every theme supports BOTH flat AND raised dynamically; every theme supports BOTH desktop AND mobile dynamically. A direction is NOT "the raised theme" or "the mobile theme" — it's a personality. Per Phase 3.2 architecture lock, the consumer toggles `raised` and `platform` exports on whichever theme they pick.

- **Anti-cyberpunk + anti-texture + universal-axes-still-work filter audit is mandatory per direction.** Each direction must survive all three filters; if a direction doesn't, it's redesigned or replaced.
- **Execution may expand survey if needed (D-03c).** No escalation required — research-quality is pre-approved by user (2026-05-06).
- **User-approval checkpoint is text-level**, not visual. Locks direction intent (names, palettes, personalities, flat/raised behavior, mobile-sizing notes) before expensive mockup generation in Phase 3.4.
