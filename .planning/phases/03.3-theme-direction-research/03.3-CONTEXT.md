**Derive 5 candidate theme directions from scratch** in the flat-MD3 + extruded-flat idiom, applying the user's per-direction feedback from the Phase 3 redirect as **DNA inputs** (NOT as name carryovers). This phase is the missing piece between **design language** (Phase 3.1 — what flat MD3 + Flat-3D Game UI looks like in general) and **mockups** (Phase 3.4 — what each specific theme looks like rendered). Without this phase, mockups would default to re-rendering v0 names through a new filter, which is not the same as deriving the *best* 5 directions for the new visual identity.

**In scope:**
- Survey ~10-15 commercial flat-MD3 game UI themes (mobile games, web apps, MD3 Expressive showcases) for color/personality validation
- 5 candidate theme directions, each with:
  - **Name** — descriptive, evocative; PascalCase form for the future subclass `class_name`
  - **Base color** — hex, with rationale (warm/cool/neutral; saturated/muted; light/dark)
  - **Accent color** — hex, with rationale; WCAG AA contrast pair against base color verified
  - **Personality summary** — 2-3 sentences (e.g., "playful + childish + mobile-game-friendly", "professional dark minimal iOS-like", "warm + welcoming + colorful arcade-by-day")

### Theme Direction Derivation Strategy

- **D-01 (HARD RULE — NO v0 CARRYOVERS):** New direction names, palettes, and personalities are **NOT inherited** from v0. Each new direction is derived **fresh** from (a) the user's new goals/restrictions, (b) the user's reactions to each v0 direction (treated as **DNA inputs**, not as namesakes), and (c) Phase 3.1 research findings. **A new direction MUST have a different name from any v0 direction**, even if its palette is loosely informed by v0 DNA. This prevents lazy renaming and forces fresh thinking in the flat-MD3 idiom.
- **D-02 (Primary inputs, in priority order):**
  1. **User's new goal:** "colorful, flat and modern UI. Not outdated 3d, texture and engraving... It can still remain colorful and playful and expressive." (verbatim from 2026-05-04 redirect)
  2. **User's hard restrictions:** No textures. No patterns. No embossing. No painterly/leather/wood/grunge backgrounds. No gradients on chrome. Anti-cyberpunk (no synthwave/neon-noir/dystopian).
  3. **User's exemplar references:** [hcgamestudios flat-game-ui-for-mobile-games](https://hcgamestudios.itch.io/flat-game-ui-for-mobile-games), [fajrulaslim UI Button Flat Design](https://fajrulaslim.itch.io/ui-button-flat-design) — the user's literal "this is what I want" examples.
  4. **User's per-v0-direction reactions** (see D-04 below) — treat as DNA, NOT as names.
  5. **Phase 3.1 findings:** MD3 + MD3 Expressive design language affordances; Flat-3D Game UI extrusion patterns.
- **D-03 (5 directions cover personality space, NOT v0 carryovers):** The 5 directions should span distinct personality archetypes derived from the inputs above. Each direction must:
  - Have a **NEW name** (not Midnight Marquee / Cabinet Chrome / Prize Pop Plaza / Orbital Playdeck / Boardwalk Sunset)
  - Be derived from the user's goals + restrictions + DNA, NOT from "let's reskin v0"
  - Demonstrate a distinct personality (so v1 ships variety, not 5 similar dark themes)

### User Reactions to v0 Directions (DNA inputs to new directions)

- **D-04:** The user's per-v0-direction feedback (verbatim from 2026-05-04 redirect, captured in REDIRECTED.md) maps as DNA — **what to extract, what to drop**:

  | v0 Direction | What user LIKED (DNA to extract) | What user REJECTED (DROP) |
  |--------------|----------------------------------|---------------------------|
  | **Midnight Marquee** | Color palette (LDtk-like, arcade vibe, dark with saturated accents) | 3D elements; textured background panels |
  | **Boardwalk Sunset** | Some appreciation for "more flat and simple" feel | EVERYTHING ELSE — **HATED MOST**; warm/leather/old-fashioned background; textured background; rejected entirely |

## Specific Ideas

- **The user explicitly asked for a phase that researches theme directions and generates 5 new themes per their goals.** That's Phase 3.3's exact mandate.
- **Don't carry v0 names by default.** v0 names (Midnight Marquee, Cabinet Chrome, Prize Pop Plaza, Orbital Playdeck) are DNA, not labels. New directions may use different names that better fit their flat-MD3 identity.
- **5 directions span personality space.** v1 user approves N (typically 1-3) at the Phase 3.4 gate, but Phase 3.3 produces 5 to give variety options.
- **MD3 Expressive is the design language affordance for "colorful + playful + expressive"** without textures. The 5th direction (or any direction) should leverage MD3 Expressive's saturation + personality.
- **Anti-cyberpunk + anti-texture filter audit is mandatory per direction.** Each direction must survive both filters; if a direction doesn't, it's redesigned or replaced.
- **User-approval checkpoint is text-level**, not visual. Locks direction intent (names, palettes, personalities) before expensive mockup generation in Phase 3.4.
